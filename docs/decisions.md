# Decisions (append-only, 1–3 lines each)

- 2026-10-23 Capture = native iOS Broadcast Upload Extension; no video leaves the phone.
- 2026-10-23 Free Apple Personal Team signing only; never require the paid program.
- 2026-10-23 No App Group dependency: extension uploads directly; config compiled from git-ignored xcconfig.
- 2026-10-23 Skip = leaving the game (board voided, no end screen). 4x4 only, no Qu tile.
- 2026-10-23 Phone logic split: sampler (pixels→numbers) + state machine (numbers→events); fixtures are numeric CSVs.
- 2026-10-23 Xcode project generated by XcodeGen from `ios/App/project.yml`; `.xcodeproj` not committed.
- 2026-10-23 Server stack: FastAPI + SQLite (SQLModel/Alembic) + Huey(SQLite); web: React+Vite+TS PWA.
- 2026-10-24 NWL dropped (licensed). Base dictionary = YAWL (public domain); ENABLE marks common words. Both committed in `dictionaries/`.
- 2026-10-24 Evidence for YAWL over ENABLE: GamePigeon accepted CLOTTER(S), LOTTER(S) on board LCMEORSIETRATDIM (YAWL yes, ENABLE no).
- 2026-10-24 End screen shows WORDS count + top 15 words only → reconcile on score + word count + visible words.
- 2026-10-24 VIEW ALL WORDS unlocks after the opponent plays → separate AllWordsRecord, matched to its board by found words; boards wait as `pending`.
- 2026-10-24 Repo root = ~/Projects/wordhunt; `$WH_DATA` = repo/wordhunt-data (git-ignored).
- 2026-10-24 Reference lists (wordhunt.org etc.) fetched manually, never at runtime, never committed.
- 2026-10-24 Repo: the empty GitHub clone's `.git` was moved up into ~/Projects/wordhunt (repo root per CLAUDE.md); repo-local git identity set.
- 2026-10-24 Schema v1: `release_state` is the §2 enum (valid_new|already_found|not_a_word), not free text; records forbid extra fields; tiles 0–15 validated. Python field `schema_` aliases JSON `schema`.
- 2026-10-24 iOS: `Base.xcconfig` (committed) `#include?`s the git-ignored Signing/Config files; without Signing.xcconfig the build is unsigned (CODE_SIGNING_ALLOWED=NO) so the compile check works anywhere.
- 2026-10-24 iOS: the extension bundles `fixtures/calibration/iphone-1206x2622.json` as a resource ("compiled in"); patches are scaled by buffer size / 1206×2622.
- 2026-10-24 App Groups probe is opt-in: set WH_APP_GROUP + WH_EXTENSION_ENTITLEMENTS in Signing.xcconfig; the diag reports app_group_configured/available.
- 2026-10-24 Swift models: IDs are lowercase UUID strings (lossless with Python); dates on the wire are ISO 8601 UTC with ms precision (WHJSON coder). Tests also decode fixtures/expected/*.json once S1 creates them.
- 2026-10-24 Web: TypeScript pinned to 6.x (TS 7 native has no JS API; openapi-typescript needs it). API types: tools/export_openapi.py → web/openapi.json → pnpm -C web gen:api → src/api/schema.ts (committed); client = openapi-fetch.
- 2026-10-26 S0.T6: frames are streamed from ffmpeg (rgb24, fps=30) straight into the sampler instead of writing ~75 GB of PNGs per recording; `extract_frames.frame_at()` pulls single frames on demand. Output = `$WH_DATA/frames/<name>/samples.csv.gz` + meta.json.
- 2026-10-26 Colour domains differ (PNG = Display P3, video = BT.709); the calibration keeps `resting_rgb` (PNG) and `resting_rgb_video` (oracle). The phone domain will be measured from /diag tiles_rgb in S0.T15.
- 2026-10-26 S0.T7: board-count criterion (35–60) can't be met by this data: session1 is a 10-min session with 21 boards, fully accounted for (6×80.8 s played + 15 skips + menus). Accepted 21; played boards all have end frames.
- 2026-10-26 allwords1 holds its own 6 boards (played second, all-words viewed right after), so §3.6 matching runs over boards from both recordings.
- 2026-10-26 review.html embeds its crops as data URIs (one portable file); boards.csv columns: recording,seq,letters,status.
- 2026-10-26 Acceptance = the live WORDS count rising right after a release (digit templates on the banner); release colour is kept as `colour_state`. Same signal is available on the phone.
- 2026-10-26 Board image/letters are taken ≥ 0.8 s after a board opens (slide-in animation); the phone must wait the same before saving the board crop.
- 2026-10-26 Letter/digit templates are committed in fixtures/templates/ (52 KB) so tests and the phone port can use them; masters in $WH_DATA/templates/.
- 2026-10-26 Word resolution: align traced tiles to solver paths (missing + extra tiles); a clean contiguous trace of a non-dictionary word is an OOV candidate (cost 1). Board-level search enforces distinct words, Σ points == end SCORE, visible words present.
- 2026-10-26 Visible-word snapping is constrained by the points column (points → length); unread points are "unknown", not a failure.
- 2026-10-26 PLAN mismatch (§1/§3.5): masked rows show ONE "?" (not one per letter); length comes from the points column. VIEW ALL WORDS reveals only the player's first 20 found words. §3.6 matching therefore = revealed words are the list-order prefix of a board's accepted words (≥80% overlap after snapping), not per-length found counts.
- 2026-10-26 Scroll tracking: 1-D profile SAD with a pull towards the previous shift (rows repeat every 61 px); word crops only from still frames; gap = cost > 25 or overlap < 300 px.
- 2026-10-26 S0.T13: traces need 30 processed fps during play (15 fps loses short swipes and tiles); menus/all-words can drop to 15 fps to save power.
- 2026-10-26 S0 gate PASS → GO. ReplayKit delivers 884×1920 420f on iPhone 17 Pro, so the extension scales calibration coordinates by buffer size (already in the probe).
- 2026-10-26 Companion app opens the system broadcast picker from its own labelled button (the picker's icon is invisible on a dark background).
- 2026-10-26 Schema v1 semantics (no structural change): AllWordsRecord.shifts_px[k] = scroll offset of frames[k] from frames[0]; gap_flags[k] = a gap occurred between crops k-1 and k. Crops are taken every ~0.5 viewport, preferring still frames.
- 2026-10-26 S1: the state machine is streaming (feed one row, no look-ahead) with 3-frame screen confirmation and a replay of held-back frames; ids are uuid5(session, seq) so outputs are deterministic for fixtures/parity.
- 2026-10-26 S1: all-words parsing is grayscale only (yellow bar ≈ 234, tan ≈ 189 luma), same code for S0 tools and the server; the colour-frame parser was removed.
- 2026-10-26 S1: fixtures omit the 64 profile columns and use JPEG crops (q75–90) to stay under 2 MB; only digits templates are exported as JSON (the phone does not read letters).
- 2026-10-26 Upload contract (S2.T4 client; S3.T2 server must match): multipart POST /v1/boards | /v1/allwords, `Authorization: Bearer`, `Idempotency-Key: <board_id|record_id>`; part `record` (record.json, application/json) + one `files` part per image (filename = reference in the record, image/jpeg). 2xx/409 = done, 401/403 = stop, other 4xx = parked in `failed/`, 5xx/network = backoff 1 s→5 min ±20%.
- 2026-10-26 Crop references are `*.jpg` (grayscale JPEG, q≈0.8) in both machines. Live capture: the Swift machine calls `onCropFrame` when it picks the current frame; past-frame requests come from CropStore rings (6 end frames, 10 still list frames, latest board frame).
- 2026-10-26 S2.T5: the extension uses TileStates.phone (resting measured on device; selected states and screen thresholds provisional = recording values) and posts the latest sample's ROI values in /diag so the S3 live session can confirm or fix them. Sampler cost (Mac, release): 0.4 ms board frame, 3.3 ms all-words frame at 884×1920.
- 2026-10-26 Uploader treats 404/405 as retry (server not yet updated), so records captured before S3 ships /v1/boards are kept, not parked.
